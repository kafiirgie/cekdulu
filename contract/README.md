# contract/ — the FE ↔ BE agreement

This folder is the **promise** between frontend and backend. As long as both sides follow it, every lane can work in parallel without waiting on each other.

| File | Contents | Used by |
|---|---|---|
| `rules.json` | Checker catalogue, "Yang tidak diceritakan" (what they didn't tell you) cards, **all rules + their thresholds**, quota, Tanya (Ask) refusal regex | BE (rule thresholds), FE (Methodology page, labels) |
| `examples/*.json` | Example request/response per endpoint (MGLV, MDKA, Tanya, Radar) | FE mock mode, BE mock mode, tests |
| `../frontend/src/lib/contract.ts` | TypeScript types for the shapes below | FE |
| `../backend/app/schemas.py` | Pydantic models for the same shapes | BE |

The test `backend/tests/test_contract.py` validates every example against the Pydantic models (unknown field = failure). The TS types in `contract.ts` aren't checked automatically yet, so keep them in sync by hand when changing the contract.

## Ground rules

1. **Changing the contract = its own PR** labelled `kontrak`, announced in the group, and approved at least by the owners of Lane A (FE) and Lane B (BE).
2. Change all three places together: `examples/`, `schemas.py`, `contract.ts`.
3. Raw numbers as decimals / full Rupiah (`0.25` = 25%, `14650` = Rp14,650). **The FE does the formatting**, using `fmt`: `pct` · `rp` · `int` · `num` · `x`.
4. Every card must have `sources[]` (name + date). A "tidak bisa dicek" (can't be checked) card may leave it empty.
5. Rule IDs (`rule_id`) must exist in `rules.json`. Tests fail otherwise.

## Endpoints

| Method | Path | Purpose | Owner |
|---|---|---|---|
| POST | `/api/klaim` | Split text/screenshot/ticker → claims + the checkers to use | Lane C |
| POST | `/api/cek` | Run the rules → verdicts, cards, form, `steps` for the animation | Lane B |
| POST | `/api/tanya` | Follow-up questions from the numbers on a card; refuses investment advice | Lane C |
| GET | `/api/modul/free-float` · `/api/modul/free-float/{ticker}` | Free Float Radar | Lane D |
| GET | `/api/modul/komoditas?jenis=` · `/api/modul/komoditas/{ticker}` | Stock vs commodity | Lane D |
| GET | `/api/rules` | Contents of `rules.json` (for Methodology) | Lane B |
| GET | `/api/health` | Status + data mode (`mock` / `fixture` / `live`) | Lane B |

`/api/tanya` → `card` is the `claim_id` (e.g. `c1`) for a claim card, or `u0`, `u1`, … (index) for a "Yang tidak diceritakan" card.

The `X-Device-Id` header (a UUID generated by the FE and stored on the device) is used for the 5 checks/day quota.

### Allowed values

- `verdict`: `sesuai` (matches the data) · `menyesatkan` (misleading) · `tidak_sesuai` (contradicts the data) · `tidak_bisa_dicek` (can't be checked) · `info`
- `form[].status`: `temuan` (finding) · `aman` (clear) · `modul_aktif` (module active) · `tidak_relevan` (not relevant) · `data_kurang` (insufficient data) · `gagal` (failed)
- `check`: see `rules.json → checks[].id` and `untold[].id`

> The numbers in `examples/` are taken from FINAL_PLAN §6 (snapshot 29–30 Sep). They are **shape examples**, not a source of numbers. Numbers for the video must come from fixtures.
